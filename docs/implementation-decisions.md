# Implementation decisions

1. No existing application source was attached; the workspace contained three specification pairs and the master prompt. This is a new repository, not a patch to an unseen prior implementation. Word/Markdown text was compared (99.7%–100% normalized similarity); Markdown owns implementation details.
2. Locked stack retained. Sites hosting was not used because the deliverable is a local/VPS Bun application ZIP. Drizzle typed catalog access plus parameterized postgres-js transactions are used. SQL migrations are authoritative for triggers and constraints; models expose application columns.
3. Schema isolation: all migration/application objects use the `quickwish` schema. Migrations take a PostgreSQL advisory lock and use content checksums; no unrelated tables are dropped or reset.
4. Cloudinary uses `authenticated` for source/proof/candidate; public reference uploads are explicitly separate. Server-side `private_download_url` with a 60-second lifetime is fetched and proxied; signed URLs are never returned to the buyer. Current payment/entitlement and candidate status are checked on each grant.
5. All private image formats are decoded and normalized to full-resolution WebP at quality 95. EXIF/GPS/trailing data are stripped. Full-quality means full resolution, unwatermarked delivery, not byte-for-byte preservation of an uploaded JPEG. Limits: 8 MB, 24 MP, 128px minimum, 8000px per axis, one frame.
6. Direct uploads are server-mediated multipart operations, replacing the illustrative sign/complete pair. Consent precedes any upload. The order may remain DRAFT after a failed upload; its guest-authorized upload route is retryable and checkout requires a valid source asset.
7. The first-50 offer reserves quote capacity atomically when issued. Reservations are not redemptions. Redemptions occur only after independent verification. Reservations persist, avoiding silent repricing or overbooking; abandoned reservations need a human policy before release. Capacity may therefore sell out before 50 payments. UI describes first 50 eligible verified buyers without a false countdown; phone uniqueness is best effort, not identity verification.
8. Intro contacts are normalized by removing the leading `+`; users should use country codes. This is not KYC. Fair promo eligibility requires manual review.
9. DEMO has no UPI intent or payable QR. A test ledger is created only by authenticated admin in DEMO. LIVE cannot call this endpoint. Both use the same financial/QC state logic and schema.
10. Groq model changed from inaccessible `llama-3.3-70b-versatile` to account-listed `openai/gpt-oss-20b`, verified with a real completion. No silent fallback to fabricated text in LIVE.
11. Business-policy defaults are proposals. LIVE startup is gated on owner approval, real payee/support settings and password hash. HTTP localhost LIVE development is permitted for integration work; production requires HTTPS and Secure cookies.
12. Auth is server-side. Strict same-Origin checking protects mutations alongside SameSite=Strict cookies. No permissive CORS. Sessions expire after 12 hours / 30 minutes idle. Guest link default 14 days. Model/API secrets are never read by Vite.
13. Hash-only create idempotency cannot reproduce a lost plaintext capability after a network failure. An already-created retry requires the original guest session; if both cookie and response were lost, use verified human support recovery. Do not assume a public code grants access.
14. Only full settled refunds are represented as REFUNDED. Partial amount disputes, top-ups and uncertain credits remain support cases/NEEDS_INFO pending an agreed human resolution. This avoids pretending a partial transfer satisfies an exact quote.
15. Gallery uses original SVG concept illustrations to keep work light. They are labelled and are not customer-result samples. LIVE seed keeps them unpublished; actual licensed portraits are a launch prerequisite. No before/after, customer ratings or turnaround claims are fabricated.
16. Test-only PGlite validates PostgreSQL DDL and API behavior without installing a server. Production and regular demo still use PostgreSQL. It does not prove multi-connection concurrency or Neon behavior.
17. Media retention defaults to 30 days for all private asset kinds, owner approval required. Cleanup is idempotent for known DB assets and emits aggregate counts. A provider timeout may have uploaded a remote asset before returning an error; orphan reconciliation, backup deletion, and local operator-copy removal require operational review. Do not infer cleanup success from an upload timeout.
18. Financial history and audit rows are intentionally retained. Media deletion does not automatically erase accounting/contact records; a comprehensive jurisdiction-specific retention/PII minimization policy is still required.
19. Admin styles support add, public image upload, publish/hide; package availability can be paused. Business copy/credentials change via deployment environment. Gallery metadata edits, advanced analytics, configurable SLA risk dashboards and automated abandoned-reservation release are not included in this pilot UI.
20. Source files are grouped into compact route/frontend modules for delivery. As the product grows, split domains and replace broad transaction row types with explicit service DTOs. Do not interpret typecheck success as an independent security audit.
